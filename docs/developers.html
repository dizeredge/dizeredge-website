Documentation/Reference

Build & architecture

Native Windows and Android interfaces share transport-independent authentication and transfer orchestration.

Project boundaries

App / Android: native WPF/MVVM and Android UI, lifecycle and platform consent. Core: models, contracts and validation. Network: UDP discovery, TCP, mutual TLS, bounded protocol, streaming and receive batches. Bluetooth: Windows WinRT RFCOMM; Android uses native BluetoothSocket streams. Security: integrity and platform-protected identity integration. Infrastructure: Windows settings, filesystem and diagnostics.

Transport streams feed the same protocol. TransferSource factories open files/Android document URIs; receive-batch boundaries separate staging and commit. No HTTP file server is used. Peer names and discovery IDs never grant trust.

Build Windows

Use Windows 10 build 19041+ or Windows 11, .NET 10 SDK and the Windows SDK. From the Windows directory:

dotnet build SecureFileSharing.slnx -c Release
dotnet test SecureFileSharing.slnx -c Release
dotnet publish src/SecureFileSharing.App -c Release -r win-x64 --self-contained true -o artifacts/publish/win-x64

Compile packaging/SecureFileSharing.iss with Inno Setup 6.7.3+. Do not distribute the separate SetupSmokeTest variant. The bundled runtime removes the need for a separate .NET install. Native ARM64 requires a separate publish and hardware validation.

Build Android

Keep the sibling Windows directory: Android references portable shared projects. Use the .NET 10 Android workload, Android platform 36/build-tools 36.0.0 and a compatible JDK. From Android:

dotnet workload install android
dotnet test tests/SecureFileSharing.Android.Tests -c Release
dotnet publish src/SecureFileSharing.Android -c Release -p:AndroidSdkDirectory=C:\android-sdk -p:JavaSdkDirectory=C:\jdk

Configure AndroidKeyStore and signing properties through protected CI inputs for distributable builds. Never commit passwords or keystores. Verify the actual signed APK with apksigner and inspect its manifest with aapt2. The delivered preview uses workload 36.1.2 and Microsoft OpenJDK 17.0.14+7. Store/AAB publication remains future work.

Protocol and limits

Control messages use an SFS1 versioned, length-delimited JSON frame bounded to 1 MiB and depth 16. A manifest contains a transfer ID, expiry, relative names, Int64 lengths and SHA-256 hashes. Shared limits are 10,000 files / 16 TiB, constrained further by frame size; Android selection is capped at 100. File bytes stream through 128 KiB buffers. The receiver verifies the batch before commit and completion acknowledgement.

TCP connect timeout is 15 seconds; ordinary I/O waits are 30 seconds. Approval is bounded to 90 seconds; pairing enrollment permits a longer bounded handshake. Total work is bounded and Android may impose a shorter OS service limit. TLS compatibility chooses supported OS versions without disabling certificate validation.

Testing and release gates

Run both suites, build both native packages, verify hashes/signatures and exercise the actual installed outputs. Test physical transfers in both directions, use LAN-disabled Bluetooth tests, verify permissions, Keystore/DPAPI persistence, OEM lifecycle, multicast isolation, cancellation, disk failures and large files. A loopback/mock test must never be recorded as a Bluetooth hardware pass.
