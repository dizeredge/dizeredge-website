Documentation/Connections

Bluetooth Classic

Bluetooth uses a real native Classic RFCOMM connection with the same application-level TLS protocol as LAN.

No physical Bluetooth transfer pass is recorded for 0.2.0. The native adapters compile, but radio/driver/OS interoperability remains a hardware-testing gate. BLE-only devices are insufficient.

Requirements

Both devices need Bluetooth Classic/RFCOMM support, enabled radios, compatible drivers/OS access and the same app version. Android needs its Bluetooth connection permission. Windows may request first-use consent for a Bluetooth service. Bluetooth file transfer does not silently fall back to LAN.

1. Pair in system Settings

Use Windows and Android Bluetooth Settings to pair the devices first. Confirm any operating-system pairing prompt on both screens. In-app OS pairing and unpaired-device scanning are not implemented.

2. Enable the app service

Open both apps, start receiving and explicitly enable Bluetooth. Windows advertises/queries the app's RFCOMM service. Android lists system-paired devices and checks the app service when connecting. A bonded device entry alone does not prove that the other app is running or compatible.

3. Verify the application identity

Refresh, select the Bluetooth target, open the app's two-minute pairing window on both devices and choose Pair device. Compare every fingerprint group with the identity shown in the other app's Settings. OS Bluetooth pairing and application trust are separate checks.

4. Send and accept

Select files and send over the selected Bluetooth target. Review and approve the incoming offer. Progress and cancellation use the common engine; encryption and integrity do not depend solely on Bluetooth link security. To evaluate the actual radio path, disable LAN and test both directions on suitable hardware.

If connection fails

Check system pairing, permissions, Classic support, radio state, distance and that the receiving app has enabled the service. Restart the app after an OS permission change. Errors can reflect driver or Windows full-trust/WinRT access limitations. Use LAN as an explicitly selected alternative. Service UUID for diagnostics: 95762c71-55c1-445d-b07d-c46b945121de.
