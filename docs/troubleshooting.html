Documentation/Reference

Troubleshooting

Start with the connection, then identity, then storage. Keep both apps visible while testing.

My device is missing

Confirm both apps are open, Android receiving is started and both devices are on the same reachable network. Wait a few seconds, refresh and try the receiver's local IPv4 address. Guest-network isolation and VLANs can block connections even with manual IP. Check Private-network firewall access without disabling the firewall.

Pairing fails or the fingerprint changed

Open pairing on both apps for two minutes and retry promptly. Compare the entire fingerprint with the other physical screen. Reject any mismatch. A reinstall, lost key, changed identity or impersonating device may cause a change. Investigate before clearing trust and pairing again. Pairing does not authorize future offers silently.

Bluetooth is unavailable

Check that the adapter supports Classic RFCOMM, the radio is enabled, system pairing is complete, permissions are granted and both apps have enabled Bluetooth. A BLE-only adapter/device is insufficient. Android lists bonded devices, not a scan of all nearby radios. Windows driver/WinRT permissions can limit the service. Physical compatibility remains unverified for this preview.

The receiver rejects or never shows a request

Keep Android foreground for pairing and approval; background offers are rejected. Offers and approval prompts expire. Confirm the receiving host is active and available disk space is sufficient, then retry with a small file. Two concurrent protocol sessions are the limit.

Permission denied, full disk or invalid filename

Select a writable local Windows destination or a valid Android document-provider folder. Free space for both private receipt and export when using Android. Source grants may expire; reselect documents. Rename unsupported Windows reserved names, trailing spaces/dots or path conflicts before sending. Paths are validated consistently across both platforms.

A transfer stopped or a hash failed

Keep the source unchanged, check network/radio stability and retry. Hash mismatches and source changes fail the batch. Cancel closes active connections. Pause/resume and automatic recovery are not supported. After process termination, private partial files may remain; they are not completed receives. If only the final acknowledgement failed, inspect the receiver for an already verified folder before sending again.

I cannot find files on Android

Receipt first goes to private app storage. Use Receive files → Save latest received files to folder. If export fails, choose another writable provider and retry; the private originals remain. A provider may leave a partial export after failure. Export wanted files before uninstalling.

Useful diagnostic details

Record app version, OS version, connection type, exact error, whether manual IP works, adapter/driver and permission state. Include filenames only if safe. Never share private keys or file contents. Windows developers can run SecureFileSharing.exe --transport-probe for identity/capability diagnostics; this is not a radio transfer test.
