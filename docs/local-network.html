Documentation/Connections

Local Wi-Fi & Ethernet

Share on the same local network without an internet connection. Wi-Fi and Ethernet use the same encrypted TCP transfer engine.

Automatic discovery

Open both applications and start Android receiving. Devices announce over IPv4 UDP multicast every three seconds. Nearby entries are deduplicated by public identity fingerprint and expire after 15 seconds without announcements. Network adapter addresses are periodically re-evaluated. Names and discovery entries do not authenticate a peer.

Connect by local IP

If a device does not appear, find the receiver's local IPv4 address in its receiving status or system network settings. Enter it on the sender's Send files screen, use the receiver's configured transfer port and pair. Use private, link-local or loopback IPv4 addresses. Public internet endpoints are rejected; IPv6 is not supported in this preview.

Network requirements

PurposeDefault
File transferTCP 45832
DiscoveryUDP 45831
Multicast group239.255.83.70, TTL 1

Windows configuration supports discovery and transfer ports. If changed, ensure both peers agree on discovery and use the receiver's correct TCP port. Restrict Windows Firewall access to the intended Private network. The installer does not create automatic firewall rules. Never forward these ports on your router for this app.

When discovery cannot work

Guest Wi-Fi/client isolation, VLAN boundaries, multicast filtering, VPN routing and disconnected adapters may block discovery or reachability. Manual IP bypasses multicast filtering; it cannot bypass isolated clients, routing or blocked TCP. Use a network where the two devices can communicate directly, or evaluate Bluetooth.

Pairing and approval still apply

Being on the same network does not make a device trusted. Open the two-minute pairing window and compare the complete fingerprint against the other physical screen. Every offer still requires receiver approval. TLS protects the channel; SHA-256 checks received contents before commit.
