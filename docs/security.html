Security & privacy

Approve the device, approve the offer, and verify the received bytes. Security depends on all three steps.

Identity and trust

Each app generates a persistent RSA-3072 certificate. TLS validation checks certificate dates, the fixed application hostname, key bounds, a custom-root chain and the exact pinned SHA-256 fingerprint. Unknown incoming identities are rejected unless the two-minute pairing window is open. Compare all fingerprint groups against the other physical device. Never approve based only on a display name or an unexpected prompt.

Windows protects the stored identity with current-user DPAPI. Android wraps its identity with AES-256-GCM using a non-exportable Android Keystore key. Forget paired devices removes all stored peer pins and cancels active protocol work. Individual peer removal and automatic identity rotation are not implemented; certificates expire after five years.

Encrypted connections

LAN and RFCOMM both carry mutual TLS. TLS 1.3 is used where supported, with secure TLS 1.2 compatibility for older systems. Certificate validation is not disabled. TLS resumption and renegotiation are disabled. Offline self-signed identities use pinned application trust rather than an internet certificate authority/revocation service.

File safety

Every offer requires explicit receiver approval. Names, relative paths, sizes, counts and protocol frames are bounded. The destination rejects traversal, invalid Windows names, conflicting paths and reparse/link routes. Files stream into a fresh private staging folder; only a complete SHA-256-verified batch becomes a received folder. Existing files are not replaced. The app never automatically executes received content.

SHA-256 validates transfer integrity, not whether a file is harmless. Treat received executables and documents as untrusted content. Network operation has deadlines, unauthenticated rate limits and bounded sessions/buffers.

Privacy

No app accounts, cloud storage, internet relay, analytics, public HTTP file endpoint, payment or subscription is included. LAN discovery broadcasts a display name, public identity fingerprint, protocol version and listener port to the local network. Do not put sensitive information in a device name. Android document providers may have their own network behavior; choose local providers for offline use.

This static website has no analytics, accounts, cookies set by its own scripts, third-party fonts or tracking scripts. The hosting provider may maintain access logs or apply its own access controls. Downloading the apps from the website requires access to the host.

Known boundaries

A compromised OS, malicious administrator, same-user malware, rooted device or malicious document provider is outside the protection boundary. Interrupted process termination can leave private partial files. Destination race hardening, key rotation, physical interoperability and independent security review remain release gates. Preview signing and successful tests are not production certification.

Reporting an issue

This preview does not yet publish a monitored security contact. Report issues privately to the DizerEdge distributor who supplied your build. Do not include private keys, pairing material or confidential file contents in reports. A public production release needs a supported disclosure channel.
