Documentation/Applications

Android app

A native Android client for offline file sharing, with system document pickers and explicit receiving controls.

Install and update

  1. Download the Android APK. Requires Android 8.0/API 26 or later and ARM64 or x86-64 hardware.
  2. Verify the APK checksum. If you choose to install it, temporarily allow installation from the browser or file manager you used, then open the APK.
  3. Follow Android's installation prompt. Restore that source's installation permission afterward if you no longer need it.
This APK is development signed. It is not a Play Store release or a production publisher identity. An installed app with a different signing key cannot be updated with this APK. Export wanted received files before any uninstall.

Start receiving

Tap Start receiving. A visible data-sync foreground service keeps the receiving host active. Keep the app in the foreground for pairing and each incoming approval: background offers are rejected. Approved transfers may continue through the service, subject to Android duration, battery and OEM limits. The notification's Stop receiving action stops the host and cancels active work.

Send documents

Open Send files and use the system picker to choose up to 100 files. Prefer local document providers for offline use. Select the receiver or enter its local IPv4 address, then pair and compare full fingerprints. A cloud-backed provider may need its own connection; the app cannot control another provider's network behavior.

Sending a source folder is not implemented. Android can receive relative file/folder structures sent by Windows.

Export your received files

Received files are checked and committed to private app storage first. Open Receive files → Save latest received files to folder and choose an accessible destination through the Android folder picker. Export creates a new folder. If a provider rejects the copy or permission expires, the verified private original remains available for retry.

Uninstalling Android removes private received files and the app identity. Export files you want to keep. Process termination can leave private partial staging files; this release has no automatic recovery journal.

Permissions

  • Bluetooth / Nearby devices: requested when you explicitly enable Bluetooth, for connections to system-paired devices. No unpaired scan or location permission is requested.
  • Notifications: optional on Android 13+, configurable in system Settings. The receiving service still follows Android's foreground-service rules.
  • Documents/folders: scoped access through the system picker. No broad storage permission.
  • Network, multicast and wake lock: for local sockets/discovery and active transfer work. The INTERNET permission is required for LAN sockets; the app has no cloud transfer feature.

Updates, identity and limitations

Updates with the same signing key normally retain app data; uninstalling removes the private identity and requires pairing again. History is session-only. Pause/resume, durable recovery and named individual peer management are pending. Android platform execution has not been validated on a phone/emulator in this environment; see test evidence.
